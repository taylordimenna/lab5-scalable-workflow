# lab5-scalable-workflow
Contains my work for Lab 5: Scalable Workflow

## Setup
### 1. Clone the repository to your local computer.
Run the following command:

    git clone https://github.com/taylordimenna/lab5-scalable-workflow.git

### 2. Move into repository
Run the following command:

    cd lab5-scalable-workflow

You are now inside the ```lab5-scalable-workflow``` directory.

### 3. Set up Python environment
This workflow requires Python, pandas, Matplotlib, and Snakemake. Miniforge or mamba must also be installed before running.

To create a new environment in miniforge or mamba, run:

    mamba create -n lab5 -c conda-forge python=3.12 snakemake pandas matplotlib -y

### 4. Activate environment
Run the following command:

    mamba activate lab5

### 5. Verify Snakemake
To verify that snakemake is installed, run the following command:

    snakemake --version

The version number should be displayed

### 6. Perform a clean full run
#### Dry run
To run a dry run prior to the clean full run, run the following command:

    snakemake -n

#### Remove generated outputs
Remove all outputs that were privously generated by snakemake by running:

    snakemake --delete-all-output

#### Run clean full run
Run the following command:

    snakemake --cores 2

#### Verify outputs
To check that all four output files were created, run:

    ls -lh results/cleaned_samples.csv results/patient_feature_table.tsv reports/summary.txt reports/summary_figure.png

### 7. Perform partial rerun
This partial rerun should show that Snakemake only reruns the stages that were affected by an upstream change. Because of this, this step should only performed after the completion of the clean full run.
#### Clean and run a dry run
Run the following command:

    snakemake -R clean_samples -n -p

The ```build_patient_features``` rule should not run because its inputs have not changed.

#### Run partial rerun
Run the following command:

    mkdir -p evidence
    snakemake -R clean_samples --cores 2 2>&1 | tee evidence/partial_rerun_terminal_output.txt

This will force the ```clean_samples``` rule to be reran. Because the ```summary_report``` depends on this, it will also be regenerated. The ```patient_feature_table.tsv``` will not be rebuilt.

```partial_rerun_terminal_output.txt``` will be created and show evidence for this partial rerun occuring.

#### Verify outputs
To check that only some of the files were created, run:

    snakemake -n

## Repository Contents
The ```data``` folder contains:
- ```cohort.bd``` is the original SQLite database containing the 566 patient records used to build the feature table.
- ```messy_samples.csv``` is the original unstructured sample dataset used for the regex-based cleaning.

The ```evidence``` folder contains:
- ```full_run_terminal_output.txt``` is the saved terminal output from the clean full run, demonstrating that all three stages were completed.
- ```partial_rerun_terminal_output.txt``` is the saved terminal output from the partial rerun, demonstrating that only the cleaning and summary stages were completed.

The ```feature_table``` folder contains:
- ```build_feature_table.py``` is the Python script used to query the SQLite database and build ```patient_feature_table.tsv```.

The ```reports``` folder contains:
- ```generate_summary.py``` is the Python script used to generate ```summary_figure.png``` and ```summary.txt``` from ```cleaned_samples.csv``` and ```patient_feature_table.tsv```.
- ```summary_figure.png``` is the figure displaying the enrollment site and tumor stage counts.
- ```summary.txt``` is the report summarizing ```cleaned_samples.csv``` and ```patient_feature_table.tsv```.

The ```results``` folder contains:
- ```cleaned_samples.csv``` is the output CSV file for ```clean_up_samples_regex.py``` which contains the structured CSV file data.
- ```patient_feature_table.tsv``` is the final table containing the 566 patient records.

The ```scripts``` folder contains:
- ```clean_up_samples_regex.py``` is the Python script that codes for the creation of ```cleaned_samples.csv``` with regex-based cleaning.

The ```sql_queries``` folder contains the SQL queries and script for running them.
- ```query_1.sql``` counts the protein-altering mutations for each patient and gene.
- ```query_3.sql``` gets patient level clinical and sample features. 

```Snakefile``` contains the snakemake workflow.

```.gitattributes``` contains the formatting and line endings for the text files.

```.gitignore``` contains the files that should not be committed to the repository.

```AI_USAGE.md``` contains information about any AI tools used to help complete this lab.

```README.md``` contains the repository contents and all the instructions needed to run it.
