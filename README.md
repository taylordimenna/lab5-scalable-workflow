# lab5-scalable-workflow
Contains my work for Lab 5: Scalable Workflow

## Setup
### 1. Clone the repository to your local computer.
Run the following command:

    git clone https://github.com/taylordimenna/lab5-scalable-workflow.git

### 2. Move into repository
Run the following command:

    cd lab5-scalable-workflow

You are now inside the ```lab5-scalable-workflow``` directory.

### 3. Set up Python environment
This workflow requires Python, pandas, Matplotlib, and Snakemake. Miniforge or mamba must also be installed before running.

To create a new environment in miniforge or mamba, run:

    mamba create -n lab5 -c conda-forge python=3.12 snakemake pandas matplotlib -y

### 4. Activate environment
Run the following command:

    mamba activate lab5

### 5. Verify Snakemake
To verify that snakemake is installed, run the following command:

    snakemake --version

The version number should be displayed

### 6. Perform a clean full run
#### Dry run
To run a dry run prior to the clean full run, run the following command:

    snakemake -n

#### Remove generated outputs
Remove all outputs that were privously generated by snakemake by running:

    snakemake --delete-all-output

#### Run clean full run
Run the following command:

    snakemake --cores 2

#### Verify outputs
To check that all four output files were created, run:

    ls -lh results/cleaned_samples.csv results/patient_feature_table.tsv reports/summary.txt reports/summary_figure.png

### 7. Perform partial rerun
This partial rerun should show that Snakemake only reruns the stages that were affected by an upstream change. Because of this, this step should only performed after the completion of the clean full run.
#### Clean and run a dry run
Run the following command:

    snakemake -R clean_samples -n -p

The ```build_patient_features``` rule should not run because its inputs have not changed.

#### Run partial rerun
Run the following command:

    mkdir -p evidence
    snakemake -R clean_samples --cores 2 2>&1 | tee evidence/partial_rerun_terminal_output.txt

This will force the ```clean_samples``` rule to be reran. Because the ```summary_report``` depends on this, it will also be regenerated. The ```patient_feature_table.tsv``` will not be rebuilt.

```partial_rerun_terminal_output.txt``` will be created and show evidence for this partial rerun occuring.

#### Verify outputs
To check that only some of the files were created, run:

    snakemake -n
